⑥ FastAPI 服务、SSE 流式 与 评测体系

源码：src/insurwiki_rag/server/main.py（182 行）· scripts/evaluate.py（94 行）· tests/

1. 惰性启动（_bootstrap）

FastAPI 进程起来时不加载任何模型；第一个请求触发 _bootstrap()：load_index()（npy 矩阵 + chunks + jieba 重分词）→ KnowledgeGraph.load()（若 kg.json 存在）→ 组装 SelfRAGGraph 与 AdvisorAgent 单例存入 _state dict。好处：`uvicorn` 秒起、健康检查不阻塞、显存/内存只在真正有流量时占用。

路由输入输出（关键字段）
GET /health—{"status":"ok","model":"glm-5.3","indexed":N}（indexed 为 chunk 总数，含 wiki 回灌）

3. SSE 流式端点的实现与事件样例

实现要点：Agent 在后台线程跑，事件塞进 queue.Queue，生成器主线程逐个取出并以 event: <type>\ndata: <json>\n\n 格式 yield；worker 结束放 None 哨兵关流；响应头带 X-Accel-Buffering: no 防反向代理缓冲。

输入：

curl -N -X POST http://127.0.0.1:8010/api/agent/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"demo","message":"等待期出险能赔吗"}'

输出（事件按真实顺序逐条）：

event: intent
data: {"intent":"rag","confidence":0.92,"reason":"询问等待期保险责任条款"}

event: tools
data: {"tool_calls":[{"tool":"rag_search","args":{"query":"等待期出险能赔吗","top_n":5}},
                    {"tool":"graph_query","args":{"query":"等待期出险能赔吗"}}],
       "tool_results":"[{\"chunk_id\":\"c-9c02...\",...}]"}   // 截 1200 字

event: delta
data: {"text":"结论"}

event: delta
data: {"text":"：等待期内确诊不承担……"}        // × N 个增量

event: citations
data: {"citations":[{"chunk_id":"c-9c02fbfcf8","n":"第二十一条","policy":"XX重疾险","excerpt":"……"}]}

event: done
data: {"session_id":"demo","intent":{...},"answer":"……完整答案…","latency_ms":5230,"model":"glm-5.3"}

LLM 侧的流式来自 chat_stream：逐行读上游 SSE，兼容 Anthropic content_block_delta/text_delta 与 OpenAI choices[0].delta.content 两种事件格式；首个增量前失败仍可自动降级 fallback 模型。

4. 评测体系（scripts/evaluate.py）

flowchart LR T["qa_triples.jsonl
1500 条"] --> S["random.Random(7).sample N=60
（与切分采样的 seed=42 不同流）"] S --> H["Hit@5：retriever.search(question)
top-5 是否命中 gold evidence"] S --> L["支撑率/拒答率：前 20 条走
完整 SelfRAG.ask() 记 support_score/refused"] H & L --> R["artifacts/eval/report.json"]

Hit@5 判据（evidence_hit，两段式）

  1. 严格判据：任一 top-5 chunk 与证据文本前 60 字符互含（c.text[:60] in evidence or evidence[:60] in c.text）→ 命中；
  2. 宽松兜底：严格未中时，任一 chunk 的 bigram 与证据 bigram 重叠率 ≥ 0.6 也算命中——因为结构感知切分会给 chunk 加"第X条(续)"前缀、带 overlap，前 60 字可能不是证据开头。

实测指标（artifacts/eval/report.json，n=60）

指标值含义与解读
Hit@575%四分之三的问题，正确条款进 top-5。未命中的 25% 主要是"申请理赔要哪些步骤"这类跨条款流程型问题（证据分散在多个 chunk，单一 chunk 覆盖不全）
支撑率均值68.6%答案句子约 2/3 有证据词面支撑；这是③的 bigram 代理指标，偏保守（合规话术/免责声明句天然无证据覆盖）
拒答率15%检索为空或支撑率 < 35% 触发拒答——金融场景的"宁拒不猜"
