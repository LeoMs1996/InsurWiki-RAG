2. 向量通道：本地 bge-small-zh-v1.5 + numpy 余弦

建库时对全部 chunk 一次性 encode(..., normalize_embeddings=True)，得到 N×512 的 float32 矩阵存 artifacts/index/embeddings.npy。因为向量都归一化了，余弦相似度退化为一次矩阵点积：

# VectorStore.search —— 全库点积后取 top_k
sims = self.matrix @ qvec            # N×512 @ 512 → N 个余弦值
sims = np.nan_to_num(sims, nan=-1.0, posinf=1.0, neginf=-1.0)
idx  = np.argsort(-sims)[:top_k]     # 降序取前 20

几千 chunk 规模下暴力扫全库是最快且最简的实现（无需 ANN 索引）；nan_to_num 兜底防止脏向量污染排序。Embedder 进程级单例（get_embedder()），模型只加载一次。

3. 稀疏通道：BM25Okapi + jieba

def tokenize(text): return [t for t in jieba.cut(text) if t.strip()]
# 建库：BM25Okapi([tokenize(c["text"]) for c in chunks])
# 查询：scores = bm25.get_scores(tokenize(query))，只保留 score>0 的命中

示例：查询 "免赔额是多少" 经 jieba 切为 ['免赔额', '是', '多少']。"免赔额"作为整词命中文本中含"免赔额"的 chunk，这正是向量通道容易在长条款中稀释的词面信号。

4. RRF 融合：公式与手工演算

两路分数尺度完全不可比（余弦 ∈ [0,1]，BM25 无界），所以不用分数加权而用排名融合：

score(d) = Σ_路 1 / (k + rank_路(d))，k = RRF_K = 60

示例（top-3 演算，k=60）：

chunk向量路排名BM25 路排名RRF 计算fused
c-A131/61 + 1/630.03252
c-B411/64 + 1/610.03227
c-C2—（未入 BM25 top-20）1/620.01613

要点：双路都命中的 chunk 显著占优（≈两倍于单路冠军）；只进一路的按名次拿保底分。GraphRAG 图谱通道命中时作为第三路排名列表加入同一公式（见④），因此 from_graph 的 chunk 也天然获得加成而不是硬插队。

5. Rerank 精排：cross-encoder

RRF 融合后不直接取 top-N，而是取前 max(top_k, 3×n) 个候选交给本地 bge-reranker-v2-m3（CrossEncoder(max_length=512)，惰性加载）：

pairs  = [(query, chunk_text) for chunk in candidates]
scores = self.model.predict(pairs)          # 每对一个相关性分（可 >1 或 <0）
top_n  = sorted(zip(cand_idx, scores), key=-score)[:n]

bi-encoder（向量通道）把 query 和 doc 各自压缩成一个向量再比距离，损失交互信息；cross-encoder 把 (query, doc) 拼一起过 transformer，能识别"问的是免赔额金额、条款答的是抵扣规则"这类细粒度错配，代价是每个候选都要前向一次，所以只对 RRF 粗筛后的 ≤60 个候选做。

没有 rerank 的轻量版是 recall()：双路召回 + RRF 即返回（带 vec_score/bm25_score 原始分），供 Agent 工具和图谱通道使用，避免每次都跑 cross-encoder。

8. 参数速查与调参方向

参数默认作用点调参影响
