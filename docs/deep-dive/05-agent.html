⑤ LangGraph 保险顾问 Agent（多轮 + 工具 + 人工确认）

源码：src/insurwiki_rag/agent/advisor.py（330 行）。入口 AdvisorAgent.chat(session_id, user_input, confirmed_intent, on_event)，被 POST /api/agent/chat 与流式端点调用。

"intent": lambda s: "synthesize" if s.get("need_human") else "tools"

2. 意图识别（_n_intent）

分类器 prompt（INTENT_SYSTEM 原文要点）要求输出 {"intent":"rag|graph|calc|chat","confidence":0~1,"reason":"..."}。输入包含最近 4 条对话历史（每条截 80 字），chat_json 解析。LLM 失败时兜底 {"intent":"rag","confidence":0.5,"reason":"fallback"}。

示例输入：{"message": "30万保额，费率0.0025，保费多少钱"} →

示例输出：{"intent": "calc", "confidence": 0.9, "reason": "包含保额与费率的数值计算请求"}

Human-in-the-loop 触发条件（二选一即挂起）：① confidence < LOW_CONFIDENCE(0.55)；② 输入是"模糊指代"——长度 <8 字符或匹配 那个|这个|嗯|随便|帮我看看。挂起时 synthesize 直接把确认问题作为回答返回，工具不执行、会话记忆不写入，等用户带 confirmed_intent 重入。

3. 工具层（ToolBox，五个工具）

工具实现示例输入 → 输出
rag_search复用②的 HybridRetriever.search（含图谱第三通道），返回精简 chunk 列表{query:"等待期多久", top_n:5} → [{chunk_id, policy, section, text(截200字), scores:{rrf, rerank}} ×5]
graph_query转发 kg.query（见④）{query:"免赔额"} → {linked_entities, chunk_ids, triples}
wiki_lookup读 artifacts/wiki/index.json，title+overview+keywords 子串匹配，取前 5{keyword:"免赔额"} → [{topic_id:"T免赔额", title, overview, file}]
calculatorAST 白名单安全求值（见下）{expression:"300000*0.0025"} → {expression:"300000*0.0025", result:750.0}
compliance_check复用③的敏感词表与免责声明{text:"本产品保本保息"} → {sensitive_words:["保本保息"], disclaimer:"…"}

安全计算器：为什么用 AST 而不是 eval

def _safe_eval(expr):
    node = ast.parse(expr, mode="eval")
    allowed = (ast.Expression, ast.BinOp, ast.UnaryOp, ast.Num,
               ast.Add, ast.Sub, ast.Mult, ast.Div, ast.USub, ast.UAdd, ast.Mod)
    for n in ast.walk(node):
        if not isinstance(n, allowed):
            raise ValueError(f"illegal token: {ast.dump(n)}")   # 名字调用/属性访问一律拒绝
    return float(eval(compile(node, "", "eval")))

LLM 产出的表达式是不可信输入；先解析成 AST、白名单校验节点类型后才求值，__import__("os") 之类在 Name/Call 节点这一关就被拒绝。calc 分支还会先做口语归一化：万→*10000、×÷xX→*/、%→/100，再用正则提取"数值 费率%"两个操作数拼成 保额*费率（"30万保额费率0.25%" → "300000*0.25/100"）。

4. 工具编排（_n_tools 按意图路由）

  • rag：必调 rag_search；若 graph_query 命中三元组则追加一次 graph_query（图谱证据进生成上下文）；
  • graph：只调 graph_query；
  • calc：只调 calculator；
  • chat：不调工具（synthesize 用轻量闲聊 prompt）。

工具异常不炸图：ToolBox.run 捕获一切异常返回 {"error": ...}，错误信息本身作为工具结果交给 LLM 解释。

5. 综合生成（_n_synthesize）

输入：最近 4 条历史（各截 60 字）+ 用户输入 + 工具结果 JSON（截 3000 字）。system prompt 按意图三选一：rag/graph 用严格版（"只依据工具返回的条款/图谱证据回答…以「结论：」开头；引用格式 [条款号/合同名]"），calc 要求基于计算结果解读费率含义，chat 是简短友好回应。

流式：注册了 on_event 时改用 llm.chat_stream，每收到一个 SSE 文本增量就 _emit("delta", {"text": delta})；引用（citations）从工具结果中的 chunk_id 列表提取前 5 条。

6. 合规与会话记忆（_n_compliance）

答案过一遍敏感词检查（命中则追加合规提示），统一追加免责声明，然后把本轮 user/assistant 两条消息写入 SessionStore——内存字典，每会话保留最近 max_turns*2=16 条消息，接口设计可直接替换 Redis。注意：挂起确认轮（need_human）不写记忆，避免未完成的对话污染上下文。

7. Human-in-the-loop 完整往返示例

# 轮 1：模糊输入触发挂起
POST /api/agent/chat {"session_id":"s1","message":"帮我看看那个"}
→ {"intent":{"intent":"rag","confidence":0.40,"reason":"输入含模糊指代"},
   "need_human":true,

   "pending_confirmation":{"guessed_intent":"rag"}}

# 轮 2：用户确认后重入（reason=user-confirmed 跳过 LLM 重判）
POST /api/agent/chat {"session_id":"s1","message":"等待期出险","confirmed_intent":"rag"}
→ 正常走 intent(直通)→tools(rag_search+graph_query)→synthesize→compliance 全链路

8. 事件流（on_event 协议）

chat(..., on_event=cb) 存在时按序发出：intent →（tools：tool_calls + 截 1200 字的 tool_results）→ delta×N → citations → done（完整结果对象）。事件回调抛异常只记日志不影响主流程（_emit 内部捕获）。这个协议直接映射为⑥的 SSE 端点。
