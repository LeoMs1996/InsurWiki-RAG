④ GraphRAG 本体约束 与 LLM Wiki 知识沉淀

源码：src/insurwiki_rag/graphrag/kg.py（179 行）· src/insurwiki_rag/wiki/sediment.py（189 行）。当前实例图谱：1633 节点 / 1087 边（artifacts/graph/kg.json），Wiki 25 页（artifacts/wiki/）。

1. 保险领域本体（硬约束）

ENTITY_TYPES   = 保险产品 / 责任条款 / 免责条款 / 费率因子 / 犹豫期 / 保额 / 期限 / 被保险人群体   # 8 类
RELATION_TYPES = 承保责任 / 免除责任 / 适用费率 / 享有犹豫期 / 约定保额 / 约定期限 / 适用群体 / 关联条款  # 8 类

"本体约束"体现在两处：写入侧，add_extraction 只接收 type 落在白名单的实体、relation 落在白名单且头尾节点都已存在的关系，LLM 幻觉出的类型直接丢弃；生成侧，Self-RAG 的 generate 节点把图谱三元组以"仅可引用，不得编造其外关系"的措辞注入 prompt（见③）。

每批的 payload 把 6 个 chunk 拼接、每个截断到 400 字符并标注 chunk_id："[c-xxx] 第十三条 …"。抽取 prompt（ONTOLOGY_PROMPT，节选）要求"不确定/本体外的信息一律不抽"，输出 JSON 数组、逐 chunk 对应。

# 免赔额（费率因子）
## 主题概述
免赔额是医疗保险中的费率因子，指被保险人自行承担、保险人不予赔付的部分……
## 核心条款要点

## 常见问答
**Q：……** A：……   ← qa_by_chunk：QA 证据与 chunk 前 60 字互含即关联，每 chunk 取 2 条

回灌索引

wiki_pages_as_chunks 把每页剥掉 front-matter、截 1500 字，包装成 chunk_type="wiki" 的 chunk（policy_name="Wiki·免赔额（费率因子）"）；augment_index_with_wiki 按 chunk_id 去重后 np.vstack 新向量、jsonl 追加行。此后用户问"免赔额"，检索 top-5 里就可能直接出现这页浓缩了 8 份合同要点的沉淀页——这就是"沉淀→反哺检索"闭环。
